An acyclic schema is equivalent to a set of MVDs, one for each edge of the join tree. We will call the left-hand side of the MVD and the label of the edge in the join tree the $key$. For example the edge $AB \mathrel{\ooalign{$-$\cr\hidewidth$\smash{\raisebox{0.9ex}{$\scriptstyle\mathrm{B}$}}$\hidewidth\cr}} BD$ in the join tree defines the MVD $B \twoheadrightarrow D|AC$. The acyclic schema can be described by these two Multivalued Dependencies: $B \twoheadrightarrow D|AC$, $A \twoheadrightarrow C|BD$. The key $B$ "seperates" the attributes $D$ and $AC$ into the two different subtrees in the join tree. We will call such a set a $separator$

We will note the projection of a relation instance $R$ on the attributes $Y$ as $R[Y]$. Where $\Omega$ is a schema and $Y \subseteq \Omega$.

When trying to compress databases it is often useful to decompose a table $R$ with attributes $\Omega$ into smaller tables holding the same information as the original. A schema is a set of distinct attribute sets $S = \{\Omega_1, ..., \Omega_k\}$. We require that no set of attributes is contained in another as this would not contribute to the join. We can say that R satisfies the join dependency JD(S) when joining the projections $R[\Omega_1],...,R[\Omega_k]$ gives us exactly the table $R$. This also means that the split is lossless as no data is lost when decomposing or joining the tables.

An MVD is a special type of join dependency in which one attribute of a schema determines multiple independent values of other attriubutes.  

Fix a relation instance $R$ of size $N = |R|$, and schema $\Omega$.
For $Y \subseteq \Omega$ we let $R[Y]$ denote the projection of $R$ onto
the attributes $Y$.

Let $X, Y, Z \subseteq \Omega$. A \emph{schema} is a set
$\mathbf{S} = \{\Omega_1, \ldots, \Omega_k\}$ such that
$\bigcup_{i=1}^{k} \Omega_i = \Omega$ and $\Omega_i \nsubseteq \Omega_j$
for $i \neq j$. We say that the relation instance $R$ satisfies the
\emph{join dependency} $\mathrm{JD}(\mathbf{S})$, and write
$R \models \mathrm{JD}(\mathbf{S})$, if
$R = \bowtie_{i=1}^{k} R[\Omega_i]$.
We say that $R$ satisfies the \emph{multivalued dependency} (MVD)
$\phi = X \twoheadrightarrow Y_1 | Y_2 | \ldots | Y_m$ where $m \geq 2$,
the $Y_i$s are pairwise disjoint, and $XY_1 \cdots Y_m = \Omega$, if
$R = R[XY_1] \bowtie \cdots \bowtie R[XY_m]$. We call $X$ the \emph{key}
of the MVD and $\{Y_1, \ldots, Y_m\}$ it's \emph{dependents}, denoted
$\mathrm{key}(\phi) = X$ and
$\mathrm{dep}(\phi) = \{Y_1, \ldots, Y_m\}$. Most of the literature
considers only MVDs with $m = 2$, which we call here
\emph{standard MVDs}.

\citet{DBLP:conf/sigmod/BeeriFH77} noted that a generalized MVD can encode concisely
multiple MVDs; for example $X \twoheadrightarrow A|B|C$ holds iff
$X \twoheadrightarrow AB|C$, $X \twoheadrightarrow A|BC$ and
$X \twoheadrightarrow AC|B$ hold. We review a \emph{join tree} from \citep{DBLP:journals/jacm/BeeriFMY83}:

\medskip
\noindent\emph{Definition 2.1.} A \emph{join tree} is a pair
$(\mathcal{T}, \chi)$ where $\mathcal{T}$ is an undirected tree, and
$\chi$ is a function that maps each
$u \in \mathrm{nodes}(\mathcal{T})$ to a set of variables $\chi(u)$,
called a \emph{bag}, such that the following \emph{running intersection}
property holds: for every variable $X$, the set
$\{u \in \mathrm{nodes}(\mathcal{T}) \mid X \in \chi(u)\}$ is a connected
component of $\mathcal{T}$. We denote by
$\chi(\mathcal{T}) \stackrel{\mathrm{def}}{=} \bigcup_u \chi(u)$, the
set of variables of the join tree.
\medskip

We often denote the join tree as $\mathcal{T}$, dropping $\chi$ when it
is clear from the context. The \emph{schema} defined by $\mathcal{T}$ is
$\mathbf{S} = \{\Omega_1, \ldots, \Omega_m\}$, where
$\Omega_1, \ldots, \Omega_m$ are the bags of $\mathcal{T}$. We call a
schema $\mathbf{S}$ \emph{acyclic} if there exists a join tree whose
schema is $\mathbf{S}$. Since we required $\Omega_i \nsubseteq \Omega_j$
for $i \neq j$, one can prove that any acyclic schema with $n$
attributes and $m$ relations satisfies $m \leq n$. We say that a
relation $R$ satisfies the \emph{acyclic join dependency} $\mathbf{S}$,
and denote $R \models \mathrm{AJD}(\mathbf{S})$, if $\mathbf{S}$ is
acyclic and $R \models \mathrm{JD}(\mathbf{S})$. An MVD
$X \twoheadrightarrow Y_1|\cdots|Y_m$ represents a simple acyclic
schema, namely $\mathbf{S} = \{XY_1, XY_2, \ldots, XY_m\}$.

Let $\mathbf{S} = \{\Omega_1, \ldots, \Omega_m\}$ be an acyclic schema
with join tree $(\mathcal{T}, \chi)$. We associate to every
$(u,v) \in \mathrm{edges}(\mathcal{T})$ an MVD $\phi_{u,v}$ as follows.
Let $\mathcal{T}_u$ and $\mathcal{T}_v$ be the two subtrees obtained by
removing the edge $(u,v)$. Then, we denote by
\[
  \phi_{u,v} \stackrel{\mathrm{def}}{=}
  \chi(u) \cap \chi(v) \twoheadrightarrow
  \chi(\mathcal{T}_u) | \chi(\mathcal{T}_v).
\]
We call the \emph{support of} $\mathcal{T}$ the set of $m-1$ MVDs
associated to its edges, in notation
$\mathrm{MVD}(\mathcal{T}) =
\{\phi_{u,v} \mid (u,v) \in \mathrm{edges}(\mathcal{T})\}$.
If $\mathcal{T}$ defines the acyclic schema $\mathbf{S}$, then it
satisfies $R \models \mathrm{AJD}(\mathbf{S})$ iff it satisfies all MVDs
in its support: $R \models \phi_{u,v}$ for all
$\phi_{u,v} \in \mathrm{MVD}(\mathcal{T})$ \citep[Thm. 8.8]{DBLP:journals/jacm/BeeriFMY83}.

\section{Information Theory}

Information theroy is the mathematics of quantifying and measuring information. In our context we will be using it to measure the uncertainty in data. Entropy is the main component of information theory that is relevant to this project. It is used to calculate how uncertain a random variable is. 

Let $X$ be a random variable with a finite domain $\mathcal{D}$ and
probability mass $p$ (thus, $\sum_{x \in \mathcal{D}} p(x) = 1$). Its entropy is:
\begin{equation}
  H(X) \stackrel{\text{def}}{=} \sum_{x \in \mathcal{D}} p(x) \log \frac{1}{p(x)}
  \label{eq:entropy}
\end{equation}

\citet{DBLP:journals/tse/Lee87,DBLP:journals/tse/Lee87a} formalized the following connection between databaseconstraints, and entropic measures. Let $(\mathcal{T}, \chi)$ be a jointree. We define the following expression:
\setcounter{equation}{5}
\begin{equation}
  \mathcal{J}(\mathcal{T}, \chi) \stackrel{\mathrm{def}}{=}
    \sum_{v \in \mathrm{nodes}(\mathcal{T})} H(\chi(v))
    - \sum_{(v_1,v_2) \in \mathrm{edges}(\mathcal{T})}
        H(\chi(v_1) \cap \chi(v_2))
    - H(\chi(\mathcal{T}))
  \label{eq:J}
\end{equation}

We abbreviate it with $\mathcal{J}(\mathcal{T})$, or $\mathcal{J}$, when
$\mathcal{T}, \chi$ are clear from the context.

\section{Mining approximate acyclic schemes from relation}
MAIMON \citep{DBLP:conf/sigmod/KenigMPSS20}(Multivalued Approximate Inference Mining and NOrmalization) is the system proposed by Kenig et al. to discover MVDs and acyclic schemes in data. They describe enumeration algorithms that allow these discoveries. They also describe a method of calculating the joint entropy of a group of attributes. When evaluating their work they found that this method could be scaled to 1 million rows and 30 attributes with small amounts of spurious tuples. Where a spurious tuple is a row is a tuple not in the original database. Computing the entropy of a set of attributes is the most compuatationally expensive part of the MAIMON system. Their use of approximate MVDs allowed them to mark more schema as suitable for the compression leading to the compression working even when an exact MVD could not be found. If we now look at the red rows in Figure 2.1 we can see that by adding the row to the original table there now needs to be a new row in the BDE table. However this now means that when the tables are joined together there will be spurious table that was not in the original table. 

If we now look at the red rows in the running example we can see that if we add the 5th red row to R then we also need to add the row $a_1$, $c_1$ in $R[AC]$ as well. However this leads to a spurious tuple in our final result after the joins being a new tuple ($a_1,b_1,c_2,d_1$). In the paper they observe this and note that if only perfect MVDs and acyclic schema were taken then it would not apply widely to databases as if one row in the database changed then the whole schema could no longer be valid. Therefore they chose to use approximate MVDs and acyclic schema instead.
